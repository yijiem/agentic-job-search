# Jobflow Browser Worker — retired

New application work uses Codex's connected browser controls. Jobflow prepares a
specific application run, opens its instructions in the Codex desktop app, and
keeps the run's progress and observed employer confirmations. See
[the Codex application workflow](../../CODEX_APPLICATIONS.md).

The former Chrome/Edge companion is retained as historical source and for
reconciling work already in progress. Do not install or update it for new
applications. New worker downloads and application claims are retired.

## Existing attempts and records

Stop the companion before starting a Codex application run. A submission already
clicked may still finish; stopping cannot recall it. Check the retained employer
tab and any receipt before retrying an uncertain application.

Existing application records, reviewed materials, completion history, and
submission evidence remain in Jobflow. Reports from an existing in-flight worker
attempt can still settle its outcome. Opening a page or clicking Submit is not
proof of acceptance: record an actual employer confirmation, or retain the
uncertain outcome.

Keep any retained employer tabs until their outcomes are resolved. Once no worker
attempt remains unresolved, you can remove the old extension from Chrome or Edge.
Removing it does not delete Jobflow's database or resume library.

## Website handoff

**Open in Codex** prepares a desktop chat; the user sends the prepared request to
start. It does not launch an unattended CLI process or automatically submit an
application. **Copy instructions** is available when the desktop link cannot be
used. A hosted server directory cannot be used as a local desktop workspace.
